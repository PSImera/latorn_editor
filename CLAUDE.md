# AGENTS.md

Короткие правила маршрутизации при работе с учебными материалами в проекте `latorn_editor`.

## Общие ограничения
- Общение с пользователем — на русском.
- Для локальных Python-команд в этом репозитории используй интерпретатор проекта `.\.venv\Scripts\python.exe`, а не системный `python`.
- Читай и записывай HTML-файлы только в `UTF-8`.
- Не соглашайся с пользователем вслепую. Если предложение фактически неверно, дублирует существующее содержимое или сделает материал хуже — скажи об этом прямо и объясни почему.

## Платформа

Материалы курсов синхронизируются с платформой Latorn (https://latorn.ru). Справочник её API лежит в `docs/latorn_api/`. Иерархия: Курс → Модуль (section) → Урок (lesson) → Шаг (step). Идентификаторы — строки (cuid), курс дополнительно доступен по slug. Содержимое шага хранится на платформе в поле `block`, его схема своя для каждого типа шага и строго проверяется сервером при публикации.

## Формат файлов — канон Latorn (round-trip без диффа)

Локальные файлы должны храниться **ровно в том виде, в каком их отдаёт даунлодер при скачивании с Latorn**, чтобы цикл «выгрузил → скачал» не порождал шумных диффов. Канон:

- **Без финального перевода строки** в конце файла (`task.md`, `task.html`, `step.json`, `lesson.json`, `structure.json`, а также вынесенный код задач `precode.py` / `tests.py` / `tests/NN.py`). Даунлодер пишет контент через `content.strip()` / `json.dumps(...)` / `code.rstrip("\n")` без хвостового `\n`. Не добавляй пустую строку в конце — ни вручную, ни в Python-скриптах (`out.write("\n")` запрещён для этих файлов). Хуки форматирования `.py`-файлы кода не трогают — держи канон вручную.
- **JSON — `indent=4`, объекты развёрнуты** (каждое поле на своей строке), `ensure_ascii=False`, без BOM. Компактная запись опций в одну строку недопустима как конечный вид — она будет развёрнута. `structure.json` — `indent=2`.
- **`task.md` / `task.html` — `.strip()`** (без обрамляющих пробелов и пустых строк).
- **Пустой абзац в конце `task.html` срезается.** Веб-редактор Latorn дописывает `<p></p>` при каждом сохранении шага; `format_step_html` его снимает — и при скачивании, и в хуке. Пустые абзацы в середине текста не трогаются.
- **`task.html`, пришедший одной строкой, раскладывается по строкам** (`src/latorn_downloader/html_format.py`, функция `format_step_html`): блочный элемент — своя строка, вложенность — табами, между блоками верхнего уровня пустая строка, содержимое `<pre>` не трогается, медиа (`img`, `audio`, `video`) считается инлайновым и внутри абзаца не переносится. **Текст, уже разложенный по строкам, не трогается вообще** — курсы со Stepik размечены своим сериализатором, и переразмечать их по-своему значит получать дифф там, где содержимое не менялось. `task.md` форматтер не трогает.
- **Переводы строк — платформенные** (на Windows — CRLF): даунлодер пишет файлы через `write_text` без параметра `newline`. Не пиши файлы с принудительным LF — иначе после перескачивания git видит изменение с «пустым» диффом.

**Никогда не сохраняй `structure.json` через PowerShell `ConvertTo-Json`** — он ломает отступы (дублирует их для вложенных объектов) и экранирует `<>` как `<>`.

Форматирование выполняется автоматически хуками `PostToolUse` после каждого `Write`/`Edit`. Ручной запуск не нужен:
- `.claude/hooks/format_json.ps1` → `format_json.py` для любого `.json`: `ensure_ascii=False`, `indent=4`, без BOM, без хвостового `\n`.
- `.claude/hooks/format_html.ps1` → `format_html.py` для `task.html` и `task.md`: `content.strip()`, без хвостового `\n`, переводы строк — платформенные (CRLF); для `task.html` ещё и `format_step_html`. Хук импортирует ту же функцию, что и даунлодер, — дублировать логику разметки не нужно.

Эти хуки зеркалят `_write_json` / `_write_task_text` в `src/latorn_downloader/step_storage.py`. При правке любой из сторон (хук или даунлодер) меняй обе синхронно, иначе round-trip снова начнёт давать дифф.

## Формат текста шага: Markdown или HTML

Текст шага (`block.text`) хранится байт-в-байт как на платформе. Имя файла зависит от поля `block.format`:

- `"markdown"` → **`task.md`** — дефолт; курсы, созданные сразу на Latorn (например, `llm_api`);
- `"html"` (или поле отсутствует) → **`task.html`** — курсы, импортированные со Stepik.

Для нового локального текстового шага создавай сразу **два файла**: `task.md` и `step.json` с содержимым `{"format": "markdown"}`. Uploader подставил бы `"format"` и сам, но даунлодер после выгрузки и обратного скачивания создаст именно такой `step.json` — без него round-trip даёт дифф. Перед редактированием посмотри на существующие шаги курса и пиши в том же формате. Не конвертируй формат существующих шагов без явной просьбы пользователя.

## Вывод консоли в шаге

Ожидаемый вывод программы в материалах не выдумывается — ни комментарием в коде (`print(x)  # [1, 2, 3]`), ни блоком «вот что напечатается». Порядок: **прогнать код → снять вывод → положить картинку в папку шага**. Если у курса есть песочница с настоящим окружением, прогон идёт в ней (для `agents-pro` — `agents-pro-sendbox`, подробности в `courses/agents-pro/CLAUDE.md`). После прогона проза шага приводится в соответствие с реальным выводом, а не наоборот.

Исключение — примеры вызова функции в условии задачи (`f(1, 2)  # 3`): это спецификация, а не вывод консоли, её оставляем комментарием.

## Публичные материалы — обязательное правило

**Все материалы, которые видит студент, являются публичными.** Это включает:
- шаги уроков (`task.md`, `task.html`, `step.json`);
- поля описания курса в `structure.json` (`course_info`): `title`, `description`, `summary`, `targetAudience`, `learningOutcomes`, `formatDetails`, `prerequisites`;
- любой текст, который будет показан обучающимся.

**При создании или редактировании любого из перечисленных материалов:**
1. Загрузи `/public-materials` скилл (если он ещё не загружен в этой сессии) — **до написания первой строки текста, а не после замечаний пользователя**. Текст, написанный по памяти о правилах, каждый раз содержит одни и те же нарушения.
2. Применяй его правила: естественный русский язык, без излишних англицизмов, без «слопа», без формализма.
3. **Прогони проверку**: `.\.venv\Scripts\python.exe scripts\check_lesson_style.py <папка урока или файл>`. Она ловит то, что регулярно просачивается мимо загруженного скилла: очеловечивание («живут», «хочет»), шаблонные заголовки («Ключевые идеи», «Итоги», «Дальше по курсу»), анонсы будущих уроков, ссылки на модули по номерам, а заодно нарушения канона файла. Ошибки чинятся до того, как материал объявлен готовым.
4. После этого прочитай текст глазами на паттерны из `/humanizer-ru`: скрипт проверяет слова, а машинный ритм и пустые связки видны только при чтении.

Пункты 3 и 4 не взаимозаменяемы и оба обязательны. Загруженного скилла недостаточно — правила формулируются абзацами, а нарушаются одним словом внутри абзаца, и при генерации это не отлавливается.

Исключение: технические файлы (`lesson.json`, `step.json` с данными тестовых задач, Python-код) — к ним правила публичных материалов не применяются.

## Скрипты в `scripts/`

Общие утилиты репозитория. Запускаются интерпретатором проекта `.\.venv\Scripts\python.exe` из корня, если в описании не сказано иначе.

**Проверки и платформа**

- `check_lesson_style.py <папка урока или файл>` — проверка стиля публичных материалов, обязательный шаг перед сдачей урока (см. раздел выше).
- `list_my_courses.py` — id и slug всех курсов аккаунта, включая черновики. Только чтение.
- `install.py` — установка зависимостей проекта.

**Медиа**

- `video_to_webp.py`, `anim_to_webp_transparent.py` — ролик или анимация в WebP под лимит Latorn в 8 МБ. Движение в шаге показывается только так: плеера для своего файла у платформы нет.
- `svg_to_png.py`, `svg_fit_canvas.py`, `pad_image.py` — растеризация схем и подгонка холста.
- `build_cv_pdf.py`, `build_student_brief.py` — сборка раздаточных материалов.

**Графики и коллажи курса** (переехали из `cv-sendbox/tools/` 24 сентября 2026)

- `chart.py` — фирменный стиль графиков: прозрачный фон, серый текст, три акцента. Не скрипт, а модуль: `from scripts.chart import panel, legend, caption, BLUE, GREEN, RED, LINE`. Новый график курса начинается с импорта отсюда, а не с копирования настроек matplotlib. Подробности стиля — в скилле `/shemas`.
- `panel_grid.py` — раскладка коллажей: `from scripts.panel_grid import panel_grid, row, stacked`. Не больше двух картинок в ряд, неполный последний ряд центрируется.
- `make_cover.py` — обложка курса `computer-vision`, коллаж 3:2 из пяти панелей в `courses/computer-vision/cover.png`. Четыре панели берёт из шагов курса, пятую — из `scripts/_cover_build/`. Аплоудер обложку не отправляет, её грузят на latorn.ru вручную.

**Стенд песочницы** — запускать **интерпретатором песочницы из её корня**, а не интерпретатором репозитория:

```
.\.venv\Scripts\python.exe ..\latorn_editor\scripts\env_report.py
```

- `env_report.py` — железо, версии пакетов, доступность CUDA. Отсюда берутся числа для подписей «получено на такой-то карте».
- `smoke.py` — смоук стека: матричные операции на видеокарте, OpenCV, инференс детектора, аугментации, метрика. Печатает измеренные значения, а не «OK». Веса и кадр кладёт в `runs/weights/` той песочницы, из которой запущен, — поэтому важна рабочая директория.

## Качество Python-кода (Pylance)

Когда пишешь или правишь Python-код в `src/`, соблюдай эти правила, чтобы не порождать ошибки Pylance прямо при генерации, — не жди, пока о них сообщит пользователь:

- **Всегда аннотируй** параметры функций и возвращаемые типы. Ставь `from __future__ import annotations` в начало каждого файла ради поддержки forward-ссылок.
- **Заглушки в `TYPE_CHECKING`** внутри миксинов должны в точности совпадать с настоящей сигнатурой метода — те же имена параметров, те же типы, те же значения по умолчанию. Если настоящий метод живёт в другом миксине или классе, прочитай его перед написанием заглушки.
- **`dict.get()` возвращает `T | None`.** Никогда не передавай результат напрямую в функцию, ожидающую `T`. Либо проверь `if value is not None`, либо задай значение по умолчанию (`dict.get(key, fallback)`), либо используй `assert`.
- **Множественные включения с `.get()`** дают `set[T | None]`. Если целевой параметр ожидает `set[T]`, отфильтруй: `{x for x in ... if x is not None}` — или обращайся по ключу напрямую с проверкой.
- **Методы миксина, вызывающие методы соседних миксинов** (например `UploadWorkflowMixin`, вызывающий `upload_structure` из `StructureUploadMixin`), обязаны объявлять эти методы заглушками внутри собственного блока `if TYPE_CHECKING`.
- Перед добавлением заглушки в блок `TYPE_CHECKING` прочитай реальную реализацию и подтверди точную сигнатуру.

## Оболочка и файловая система (Windows)
- Окружение — **Windows**. Для любого чтения файлов используй специальные инструменты `Read`, `Glob`, `Grep`, а не `ls`, `cat`, `find` или `grep` через Bash.
- **Любую команду оболочки запускай инструментом PowerShell** — это не опция. Bash не разрешает Windows-пути с обратными слэшами и падает молча или с «command not found».
- Никогда не смешивай прямые слэши в путях PowerShell: на Windows это даёт ошибки «cannot access».
- Инструмент Bash полностью запрещён для любых команд, которые ссылаются на локальные пути проекта или на интерпретатор из `.venv`.

## Базовый контекст
- Прочитай `course_config.json`, чтобы взять `default_course`; используй его как активный курс, если пользователь не указал другой.
- Чтобы найти id/slug любого курса Latorn, доступного аккаунту (включая неопубликованные черновики, которых нет в публичном каталоге), запусти `.\.venv\Scripts\python.exe scripts\list_my_courses.py` (только чтение). В `course_config.json` работают и id, и slug.
- Все курсы лежат в `courses/`.
- Базовая структура: `courses/<course>/<module>/<lesson>/`.
- Папки модулей и уроков используют номера с ведущим нулём, например `03/05`.
- Урок — это последовательность шагов с единым пространством нумерации. Достоверный список шагов лежит в `lesson.json` в корне урока (`step_id` — id шага на Latorn; `null` у локальных черновиков).
- При добавлении или удалении шагов синхронизируй `stepsCount` в `lesson_info` этого урока в `courses/<course>/structure.json`; поля `createdAt`/`updatedAt` не трогай — их обновляет платформа.
- Каждый шаг хранится в своей подпапке `{pos:02d}_{type_safe}/` внутри папки урока (`type_safe` = тип с `-`→`_`), например `01_text/`, `05_choice/`, `03_free_text/`.
- **Номер шага** = поле `position` в `lesson.json`. Когда пользователь говорит «шаг 5» или «step 10», речь именно о номере позиции.
- **Тип шага** — суффикс папки после подчёркивания. Поддерживаемые типы: `text`, `video`, `code`, `choice`, `number`, `free-text`, `sorting`, `matching`, `review`.
- Чтобы найти шаг N: посмотри позицию N в `lesson.json`, прочитай поле `type`, затем открой `courses/<course>/<module>/<lesson>/{N:02d}_{type_safe}/`.
- Когда пользователь говорит «сделай шаг 10 задачей на программирование» — создай или переименуй подпапку позиции 10 в `10_code/` и обнови `lesson.json` соответственно.
- Перед правкой определи точный путь курс/модуль/урок/шаг.
- Не меняй соседние уроки, модули и курсы без необходимости.
- Не запускай масштабные рефакторинги, если задача касается одного урока.
- Теоретические шаги, шаги с тестовыми задачами и шаги с заданиями принадлежат одной и той же последовательности шагов урока.
- Когда тестовые задачи или задания добавляются после теоретических шагов, их номера должны продолжать нумерацию шагов урока после существующих теоретических.
- Практические задания можно также собрать в отдельный урок модуля, состоящий только из заданий, — включая задачи на программирование с автопроверкой и задания с проверкой человеком.
- Обычный размер урока — теория, тестовые задачи и задания вместе — около `16` шагов. Это договорённость о плотности урока, а не ограничение платформы: Latorn принимает и больше, поэтому превышение — вопрос суждения, а не ошибка.
- Примеры кода, которым нужна отдельная проверка, хранятся рядом с материалами урока в `courses/<course>/<module>/<lesson>/code_examples/<step>/`.
- **Не оборачивай `<img>` в `<p>`.** Абзац вокруг картинки даёт лишний перенос строки при отрисовке шага. Отдельно стоящее изображение пишется тегом верхнего уровня: `<img alt="…" name="01.png" src="01.png">`, без `<p>` вокруг. Форматтер медиа считает инлайновым и в абзац не заворачивает, так что бареный `<img>` всё равно окажется на своей строке. Внутри абзаца картинка допустима только тогда, когда она действительно часть текста.
- Картинки шага хранятся прямо внутри его подпапки. Новые локальные изображения нумеруются `01.<ext>`, `02.<ext>`, ... Имя файла даунлодер определяет по порядку: атрибут `name` тега (`<img name="01.png" src="...">`) → имя из `src`, очищенное от служебного хвоста Latorn (`/uploads/lesson-media/01-1785082668695-<uuid>.png` → `01.png`) → сверка по содержимому с уже лежащими в папке файлами (переименованный вручную файл не задублируется). **В HTML-шагах у каждого `<img>` пиши `name`, равный имени файла**, но не рассчитывай, что он переживёт правку: веб-редактор Latorn атрибут выбрасывает при пересохранении шага. `name` — единственная зацепка для картинок, оставшихся на CDN Stepik (`https://ucarecdn.stepik.net/<uuid>/-/crop/.../preview/`): в их URL нет ни имени, ни расширения.
- Аудио (`<audio src=...>` / `<source src=...>`, у Latorn это `/uploads/stepik/<id>/audio/<имя>.mp3`) даунлодер тоже сохраняет в подпапку шага под именами файлов с платформы, рядом с картинками. Текст шага при этом не меняется — `src` в HTML остаётся прежним (правило voice_ai: реальные URL в `<audio src>` не трогать).
- Содержимое по типу шага (`task.md` или `task.html` — по `block.format`, см. «Формат текста шага»):
  - `text` → `task.md`/`task.html` (+ `step.json`, если в `block` есть поля кроме `text`);
  - `code` → `task.md`/`task.html` + `step.json` (остальные поля `block`) + `precode.py` (`block.preCode`) + `tests.py` (код единственного сьюта; для нескольких — `tests/NN.py` по порядку). Код задачи вынесен из `step.json` в `.py`-файлы: в `step.json` у сьютов остаются только метаданные (`name`, `hidden`). Аплоудер подставляет код обратно из файлов, даунлодер — раскладывает; при отсутствии файла берётся инлайн-значение из `step.json` (обратная совместимость). Плюс `solution.py` — эталонное решение, не выгружается;
  - `review` → `task.md`/`task.html` + `step.json` (остальные поля `block`);
  - `video` → только `step.json` (`block` целиком);
  - тестовые задачи (`choice`, `number`, `free-text`, `sorting`, `matching`) → только `step.json` (`block` целиком) — без файла с текстом.
- Схемы `block` для каждого типа не описаны в документации платформы — ориентируйся на скачанные примеры того же типа в `courses/` и сохраняй все поля, которые там есть.

## Веб-редактор Latorn портит разметку шага

Пересохранение шага в веб-редакторе на latorn.ru — операция с потерями. Проверено на шаге `agents-pro-copy` 1.2/3: после правки в редакторе платформа отдаёт

- **таблицу, раскатанную в один абзац** — `<table>` со всеми `<tr>`/`<td>` превращается в `<p>&nbsp; Чат-бот Промпт-цепочка Агент <strong>…</strong> …</p>`, восстановить автоматически нельзя;
- **`<img>` без атрибутов** — снимаются `name`, `alt`, `height`, `width`;
- `<pre>` с дописанным `class="latorn-editor-code-block"` (это безвредно).

Перепроверено 5 августа 2026 на уроке 1.2 курса `computer-vision` — редактор ещё и

- **оборачивает содержимое каждой `<td>` и `<th>` в `<p>`** (таблица при этом уцелела — в отличие от случая выше);
- **дописывает ссылкам `target="_blank" rel="noopener noreferrer nofollow"`** перед `href`;
- **добавляет пустой `<p></p>` в конец шага** при каждом сохранении;
- пересобирает `<img>` в порядок `src, alt, name`.

**Сама платформа не нормализует ничего.** Проверено чтением `GET /api/steps/[id]` на шаге, который в редакторе не открывали: ячейки без `<p>`, ссылки без `target`, пустого абзаца нет — `block.text` лежит ровно в том виде, в каком его прислал аплоудер. Отсюда правило: **под канон редактора подстраиваться не надо**, надо не пускать редактор в цикл.

Практический вывод: **шаги правь локально и выгружай аплоудером**, включая вставку картинок — с 5 августа 2026 аплоудер грузит их сам (см. ниже). Если шаг всё же правили на платформе — после скачивания сверься с прошлой версией файла (`git show HEAD:<путь>` в репозитории курса) и верни потерянное; полезны там обычно только адреса загруженных картинок.

Хвостовой `<p></p>` — единственное из этого списка, что снимается автоматически: его срезает `format_step_html`, то есть и даунлодер, и хук форматирования.

## Картинки шага грузит аплоудер

Локальный шаг ссылается на файлы по имени (`<img src="01.png">`). Перед отправкой шага аплоудер (`upload_step_media` в `src/latorn_downloader/local_steps.py`) находит такие ссылки, грузит файлы через `POST /api/uploads/lesson-media`, подставляет полученные адреса `/uploads/lesson-media/<имя>-<ts>-<uuid>.<ext>` в текст **и переписывает локальный `task.html` / `task.md`**. Поэтому:

- **вставлять картинки в веб-редакторе не нужно** — именно эта привычка и порождала дифф на всём шаге;
- после выгрузки локальный файл меняется (в `src` появляются адреса платформы) — это ожидаемый дифф, а не побочный эффект;
- повторная выгрузка тех же картинок не грузит: в `src` уже адрес платформы, локальных ссылок нет;
- **изменённая картинка перезаливается сама.** Правка схемы после выгрузки раньше на Latorn не доезжала: локальной ссылки в тексте больше нет, и аплоудер файл не трогал. Теперь `find_stale_media_refs` сверяет время изменения файла в папке шага с меткой загрузки, зашитой в адрес (`01-<epoch ms>-<uuid>.png`): файл новее — грузится заново, `src` в тексте и в локальном `task.html` меняется на новый адрес. Возвращать `src` к локальному имени руками не нужно. Работает только там, где в адресе есть имя файла: у загрузок постарше (`<ts>-<uuid>.png`) и у картинок с CDN Stepik сверять не с чем;
- грузятся только медиа (`.png .jpg .jpeg .gif .webp .svg .mp3 .wav .ogg .m4a .mp4 .webm`), остальные локальные ссылки уходят как есть;
- **форматы, которые платформа не принимает, конвертируются перед отправкой.** `POST /api/uploads/lesson-media` отвечает `VALIDATION_ERROR` на всё, кроме PNG, JPEG, WebP, SVG, MP3, M4A, OGG, WAV и WebM. Поэтому `src/latorn_downloader/media_convert.py` подменяет `.gif` и `.mp4` анимированным WebP (ffmpeg, лесенка fps/качества под лимит 8 МБ), а `.svg` — растром PNG (headless Edge/Chrome). Исходник остаётся в папке шага рядом, готовый сосед переиспользуется, если он не старше исходника. Та же функция стоит за `scripts\video_to_webp.py` и `scripts\svg_to_png.py` — правь модуль, а не копии в скриптах. **Анимацию в шаг клади сразу как `.webp`**, гифку держи рядом исходником;
- атрибуты `alt` и `name` при этом остаются нашими — меняется только `src`.

Если файла нет в папке шага или загрузка не удалась, аплоудер печатает предупреждение и отправляет ссылку как есть — шаг не падает, но картинки на платформе не будет.

**Видео шага на Latorn не бывает.** Плеера для собственного файла у платформы нет: единственный видеошаг — тип `video`, и он показывает ролик с внешнего хостинга по ссылке из `block`. Внутри текста шага движение показывается **анимированным WebP** — картинкой, которую аплоудер грузит наравне с остальными и которая играет сама. Отсюда порядок: ролик прогона режется до нужных секунд и конвертируется (`scripts\video_to_webp.py`), в шаг идёт `.webp`, исходник остаётся рядом в папке шага. Живой пример — `courses/computer-vision/05/03/04_text/task.html`, тег `01.webp` со скелетом поверх наклоняющегося человека.

**Картинки в описании курса грузятся так же.** В `course_info.summary` можно писать `<img src="cover.png">`, положив файл в корень курса рядом с `structure.json`. Перед отправкой описания `_upload_summary_media` (`src/latorn_downloader/structure_upload_workflow.py`) прогоняет его через ту же `upload_media_refs`, что и шаги, и переписывает `summary` в `structure.json` на адрес платформы. Вставлять картинку в веб-редакторе не нужно — он переписывает разметку описания целиком, ровно как у шага.

Обложка курса (`coverImage`) этим не покрывается: это отдельное поле, аплоудер его не отправляет, файл загружают на latorn.ru вручную.

## Позиции шагов на Latorn — плотный ряд 1…N

Платформа требует, чтобы позиции шагов урока шли подряд без дыр и совпадений. Любой запрос, который этот ряд разрывает, возвращает `HTTP 500` с пустым телом:

- поставить шаг на позицию, занятую другим шагом;
- перенести существующий шаг за пределы `N` (на его прежнем месте останется дыра);
- «припарковать» шаг на временную позицию вида `max + 100`.

Из-за последнего пункта двухфазная парковка в `_fix_step_positions` (`src/latorn_downloader/upload_workflow.py`) не работает: припарковаться некуда. **Лог при этом вводит в заблуждение** — аплоудер печатает `moved → 13`, хотя шаг остался на прежней позиции. Результат перестановки проверяй чтением `list_steps`, а не выводом аплоудера.

Практические следствия при правке уроков:

- **Новые шаги добавляй в конец урока.** Добавление на `N+1` проходит нормально.
- Если шаг нужен по смыслу в середине, **не двигай хвост**, а переназначь содержимое существующих шагов по позициям. Тип меняется на месте: `PUT /api/steps/[id]` принимает новый `type` вместе с совместимым `block`. Недостающие шаги дописываются в конец.
- Соответствие «локальная папка → `step_id`» в `lesson.json` при таком переназначении меняется: шаг, который был `choice`, может стать `text` с тем же id. Это нормально, id — просто идентификатор на платформе.
- После такой выгрузки урок нужно скачать: часть шагов получит новые `step_id`.

## Описание курса правили на сайте — качать с флагом

`refresh_structure` по умолчанию **не забирает описание курса с Latorn**: локальный `structure.json` считается источником для аплоудера, а о расхождении печатается только предупреждение `⚠️ Поля описания курса расходятся с Latorn`. Поэтому цикл «правлю описание в веб-редакторе → качаю» сам по себе не работает, а следующая выгрузка затрёт правки локальным текстом.

Чтобы забрать описание с сайта:

```python
downloader.download_course(..., refresh_structure=True, pull_course_info=True)
```

Флаг переносит поля описания (`title`, `description`, `summary`, `targetAudience`, `learningOutcomes`, `formatDetails`, `prerequisites`, `level`, `category`, `tags`, `estimatedHours`) и `coverImage`. `summary` при этом раскладывается по строкам той же `format_step_html`, что и текст шагов, — редактор отдаёт его одной строкой и с хвостовым `<p></p>`.

Технические поля (`slug`, `price`, счётчики) остаются локальными намеренно: **`slug` на платформе меняется при переименовании курса**, а по нему курс ищется в `course_config.json`. У `computer-vision` он уже разъехался — на Latorn `...-do-prodakshna-kopiya`, в конфиге лежал `...-do-prodakshna-copy`. Чтобы это не повторялось, в `course_config.json` для него стоит id (`cmsb3ft3w00o901ne36qkl50b`), а не slug.

## Удалённые операции — запрет

**Никогда не запускай `uploader.py` и любую команду, которая изменяет данные на серверах Latorn**, без явного подтверждения пользователя для каждого конкретного запуска.

Это включает: `python uploader.py`, а также любой вызов `upload_structure()`, `upload_course()`, `update_course()`, `create_step()`, `update_step()`, `delete_step()` и т.п. через интерпретатор.

Эти операции изменяют удалённые данные и частично необратимы. После внесения изменений в `structure.json` или шаги уроков — **сообщи пользователю, что файлы обновлены, и напомни, что для синхронизации с Latorn нужно запустить uploader вручную**. Не запускай его сам.

Запросы к API Latorn только на чтение (GET: структура, уроки, шаги, аналитика, `scripts/list_my_courses.py`) разрешены без подтверждения.

## Ресёрч

- Для ресёрча актуальной обстановки — того, что реально пишут и обсуждают люди (мнения, отзывы, тренды, свежие новости по теме) — используй скилл `/last30days:last30days`. Он собирает посты и вовлечённость за последние 30 дней из Reddit, Hacker News, X, YouTube, TikTok, Polymarket, GitHub и веба.
- Это отдельный слой от `/fact-check`: `last30days` — про свежие мнения и обсуждения сообщества, `/fact-check` — про сверку фактов урока с официальными источниками. Для проверки технических утверждений по-прежнему бери `/fact-check`.

## Скиллы

- Загружай скиллы только по мере надобности для текущей задачи.
- **Проверка субагентом-студентом разрешена заранее и отдельного согласия не требует.** Скиллы `/test-tasks` и `/task-programming` предписывают перед сдачей прогнать набор через `general-purpose` субагента, который решает задачи и отвечает на тесты, имея на руках только текст урока. Это штатный шаг их рабочего процесса, а не самостоятельная инициатива: запускай его сам, когда набор готов, и показывай пользователю разбор результатов. Правило распространяется только на такие проверки; на остальные задачи общий порядок не меняется — субагент запускается по просьбе пользователя.
- Если задача правит `CLAUDE.md` или любой файл скилла в `.claude/skills/`, считай её задачей на правку правил — до применения любого более специфичного скилла.
- Если для целевого курса есть `courses/<course>/CLAUDE.md`, прочитай его и применяй эти правила вместе с выбранным скиллом.
- Схемы `block` в скиллах `/test-tasks`, `/task-programming`, `/task-rewiew` сняты с реальных шагов Latorn. Если скачанный шаг того же типа содержит поля, которых нет в скилле, — сохраняй их и верь реальным данным.

## Структура курса

- Перед правкой материалов определи целевой курс.
- Структура курса хранится в `courses/<course>/structure.json` (создаётся даунлодером). Не читай его целиком ради рутинного контекста — используй `python -m src.utils.extract_course_structure --input courses/<course>/structure.json` и опирайся на его компактный вывод.
- Когда такой разобранный вывод доступен, считай его источником истины для `course_name`, полей описания курса, названий модулей и названий уроков.
- Правила конкретного курса дополняют общие и действуют только на задачи внутри этого курса.
- Если файла правил курса нет, продолжай по общим правилам.
