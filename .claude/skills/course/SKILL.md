## Назначение

Этот скилл занимается структурой и метаданными на уровне курса — выше отдельных уроков. Он правит `courses/<course>/structure.json` — локальный источник истины для всего, что аплоудер `upload_structure()` отправляет на Latorn.

Поля описания курса (`title`, `description`, `summary`, `targetAudience`, `learningOutcomes`, `formatDetails`, `prerequisites`) — **публичный текст**, который видят студенты. **Всегда загружай /public-materials вместе с этим скиллом** при правке любого из этих полей: к ним применяются те же правила качества (естественный русский, без слопа, без лишних англицизмов), что и к шагам уроков.

Используй этот скилл, когда задача связана с:
- правкой полей описания курса;
- переименованием модулей или уроков;
- изменением порядка модулей или уроков;
- добавлением новых модулей или уроков в структуру;
- переносом урока в другой модуль;
- разбором общей структуры курса.

**Не** используй этот скилл для правки содержимого шагов урока (теория, вопросы тестов) — для этого есть `/lesson`.

## Подготовка

1. Разбери `$ARGUMENTS` на предмет имени курса. Если его нет или он неоднозначен, перечисли подпапки `courses/` и попроси пользователя выбрать.
2. Прочитай `courses/<course>/structure.json` — все правки идут только в этот файл.
3. Если есть `courses/<course>/CLAUDE.md`, прочитай его ради ограничений конкретного курса.
4. Подтверди активный курс и покажи пользователю сводку текущей структуры, прежде чем что-то менять:
   - название курса;
   - количество модулей и их названия;
   - количество уроков в каждом модуле.

## Модель данных в structure.json

```
course_id            ← id курса на Latorn (строка cuid)
course_info          ← поля уровня курса (полный объект курса из API Latorn)
structure[]          ← массив модулей (секций), отсортирован по section_position
  section_id         ← ID на Latorn, строка ("" или отсутствует = ещё не создан на Latorn)
  section_title      ← редактируемое название модуля
  section_position   ← порядок в курсе (с 1)
  section_info       ← полный ответ API Latorn (руками не править)
  lessons[]          ← массив уроков этого модуля, отсортирован по position
    lesson_id        ← ID на Latorn, строка ("" / null / отсутствует = ещё не создан)
    lesson_title     ← редактируемое название урока
    position         ← порядок внутри модуля (с 1)
    lesson_info      ← полный ответ API Latorn (руками не править)
```

Все id Latorn — **строки** (cuid), не числа. Юнитов нет — урок принадлежит модулю напрямую через `lesson_info.sectionId`.

**Не трогай** `section_info` и `lesson_info` — это кэш ответов API Latorn, он перезаписывается при следующем `refresh_structure()`. Правь только поля, помеченные как редактируемые.

> Аплоудер использует `lesson_info.title` и `section_info.title` как «последнее известное состояние на сервере», чтобы решить, отправлять ли запрос на переименование, а `lesson_info.sectionId` — чтобы обнаружить перенос между модулями. Правка этих кэш-полей ломает определение изменений, и аплоудер молча пропускает вызов API.

### refresh_structure() — семантика скачивания (побеждает сервер)

`refresh_structure()` (запускается также через `download_course(refresh_structure=True)`) забирает текущее состояние с Latorn:

- **Названия и позиции** модулей и уроков **перезаписываются с Latorn** (с уведомлением в консоли о каждом перезаписанном значении). Ручные правки, сделанные на сайте Latorn, подхватываются автоматически.
- **Локальные папки уроков переименовываются автоматически** при смене позиций (переименование в две фазы, поэтому обмены местами безопасны). Файлы `MM-LL_summary.md` внутри перемещённых папок переименовываются под новую позицию.
- Черновики (записи без `lesson_id` / `section_id`) и поля описания в `course_info` остаются локальными. Если локальные поля описания расходятся с Latorn, печатается предупреждение, но ничего не перезаписывается.
- **`pull_course_info=True`** (у `refresh_structure` или `download_course`) переворачивает это для описания: поля описания и `coverImage` берутся с Latorn поверх локальных, а `summary` раскладывается по строкам через `format_step_html`. Используй, когда описание правили в веб-редакторе на сайте: без флага скачивание его не подхватит, а следующий `upload_structure()` затрёт сайт локальным текстом. Технические поля (`slug`, `price`, счётчики) остаются локальными намеренно: `slug` меняется при переименовании курса на Latorn, а `course_config.json` может искать курс по нему.
- Ничего не удаляется: локальные записи, чьего id больше нет на Latorn, сохраняются с предупреждением.

**Следствие:** отправляй накопившиеся локальные переименования и перестановки через `upload_structure()` *до* обновления структуры, иначе обновление откатит их к состоянию сервера.

## Правила редактирования

### Поля описания курса (`course_info`)

Поля, которые `upload_structure()` отправляет на Latorn (camelCase — как в API):

| Поле | Тип | Примечания |
|---|---|---|
| `title` | str | Название курса |
| `description` | str (простой текст) | Короткое описание для каталога. **Жёсткий лимит платформы — 500 символов** |
| `summary` | HTML | Полное развёрнутое описание на странице курса |
| `targetAudience` | list[str] | Для кого курс — по пункту на элемент |
| `learningOutcomes` | list[str] | Что студент сможет делать |
| `formatDetails` | list[str] | Факты о формате (число модулей, часы и т.д.) |
| `prerequisites` | list[str] | Требуемые предварительные знания |
| `level` | str | Например `BEGINNER`, `INTERMEDIATE` |
| `category` | str | id категории на платформе |
| `tags` | list[str] | Теги |
| `estimatedHours` | int/null | Ожидаемая трудоёмкость |

Правь эти поля прямо в `course_info`. Остальные поля `course_info` не трогай (`slug`, `price`, `isPublished`, счётчики — технические поля платформы; `price` меняется только по явной просьбе пользователя).

#### Лимит длины `description` — 500 символов

`PUT /api/courses/[id]` отвергает `description` длиннее 500 символов:

```
HTTP 400 [VALIDATION_ERROR] Проверь поля курса.
details={"issues": [{"path": "description", "message": "Too big: expected string to have <=500 characters"}]}
```

Аплоудер при этом падает трейсбеком посреди `upload_structure` — остальные поля курса до отправки не доходят.

Правила:

- После любой правки `description` **проверь длину** и укоротись, если вышел за лимит:
  ```powershell
  .\.venv\Scripts\python.exe -c "import json; d=json.load(open('courses/<course>/structure.json', encoding='utf-8'))['course_info']['description']; print(len(d))"
  ```
- Не режь текст механически по границе — перепиши так, чтобы уложиться и сохранить смысл.
- Длинному тексту место в `summary`: там лимита нет (проверено на 3675 символах). `description` — короткая витрина для каталога, не пересказ программы курса.
- У остальных описательных полей (`summary`, `targetAudience`, `learningOutcomes`, `formatDetails`, `prerequisites`, `tags`) ограничений не обнаружено.

Если валидация всё же падает, конкретное поле видно в `error.details` — их печатает `_raise_for_status` в `src/latorn_downloader/api.py`. Уточнить виновника можно пробными `PUT` по одному полю за раз, но это запись на Latorn — только с явного разрешения пользователя.

При правке `summary` сохраняй корректную структуру HTML (`<p>`, `<ul>`, `<li>`, `<strong>`). `description` — простой текст с переносами `\n`.

**Картинки в `summary`** грузит аплоудер — так же, как медиа шагов: пиши `<img src="cover.png">` и клади файл в корень курса рядом со `structure.json`. `_sync_course_metadata` загружает его через `POST /api/uploads/lesson-media` перед отправкой описания и переписывает `summary` в `structure.json` на адрес платформы. Не вставляй картинки через веб-редактор — он переписывает разметку описания целиком. Обложку каталога (`coverImage`) это **не** покрывает: аплоудер это поле не отправляет, его задают на latorn.ru вручную. Списочные поля (`targetAudience` и т.п.) содержат строки простого текста, по одной мысли на элемент — HTML внутри не нужен.

### Переименование модуля

Обновляй **только** `section_title` нужной записи. Не меняй `section_position`, если заодно не переставляешь модули. Никогда не трогай `section_info` — правило кэша то же, что и для `lesson_info`.

### Переименование урока

Обновляй **только** `lesson_title` нужной записи внутри массива `lessons` её модуля. Не меняй `lesson_id` и `position`, если заодно не переставляешь уроки.

> **КРИТИЧНО — не трогай `lesson_info.title`.**
> Аплоудер определяет переименование, сравнивая `lesson_title` (желаемое) с `lesson_info.title` (последнее известное значение на сервере). Если обновить `lesson_info.title` под новое `lesson_title`, аплоудер не увидит разницы и молча пропустит вызов API — название урока на Latorn останется прежним. `lesson_info` — кэш только для чтения; аплоудер сам перезапишет его после успешной отправки.

### Перестановка модулей

Меняй значения `section_position` так, чтобы они образовывали непрерывную последовательность с 1 без пропусков. После правки пересортируй массив `structure` по `section_position`.

Всегда нормализуй позиции в непрерывный ряд с 1 перед сохранением. Порядок на сервере аплоудер чинит перестановкой в две фазы (припарковать на временные позиции, затем выставить целевые), поэтому обмены местами безопасны.

### Перестановка уроков внутри модуля

Меняй значения `position` внутри массива `lessons` нужного модуля. Нормализуй в непрерывный ряд с 1. После правки пересортируй массив по `position`.

### Добавление нового модуля

Добавь в конец `structure` новую запись:
```json
{
    "section_title": "<название>",
    "section_position": <следующая свободная позиция>,
    "lessons": []
}
```
`section_id` отсутствует — аплоудер создаст модуль на Latorn.

### Добавление нового урока

Добавь в конец массива `lessons` нужного модуля новую запись:
```json
{
    "lesson_id": null,
    "lesson_title": "<название>",
    "position": <следующая свободная позиция>
}
```
Отсутствующий или `null` `lesson_id` сообщает аплоудеру, что урок нужно создать на Latorn.

### Перенос урока в другой модуль

На Latorn урок принадлежит модулю через `sectionId` — юнитов нет. Аплоудер обнаруживает перенос, сравнивая модуль, в котором урок лежит локально, с `lesson_info.sectionId`, и отправляет `PUT /api/lessons/{id}` с новым `sectionId`.

**Шаги:**

1. Удали запись урока из массива `lessons` старого модуля в `structure.json`.
2. Перенумеруй оставшиеся уроки старого модуля (непрерывный ряд с 1).
3. Добавь **полную запись** (вместе с `lesson_id` и `lesson_info` — ничего не вычищай) в массив `lessons` нового модуля на нужную `position`.
4. Перенумеруй уроки нового модуля (непрерывный ряд с 1).
5. Перенеси локальную папку урока в каталог нового модуля и переименуй по новым позициям; соответственно переименуй `MM-LL_summary.md` внутри.
6. Запусти `upload_structure()` — он перенесёт урок на Latorn и починит позиции в обоих модулях.

### Удаление урока

1. Удали запись урока из массива `lessons` в `structure.json`.
2. Перенумеруй оставшиеся уроки, чтобы `position` оставалась непрерывным рядом с 1. Пересортируй массив по `position`.
3. **Удали локальную папку урока** `courses/<course>/<module>/<lesson_pos_padded>/` (например `courses/voice_ai/02/04/`). Через PowerShell: `Remove-Item -Recurse -Force "<path>"`.
4. **Переименуй последующие папки уроков**, чтобы их двузначные имена соответствовали новым позициям. Пример: если удалена позиция 4, переименуй `05/` → `04/`, `06/` → `05/` и т.д. Используй `Rename-Item`.
5. По умолчанию на Latorn ничего не удаляется. При `upload_structure(sync_deletions=True)` аплоудер находит осиротевший урок и просит подтверждение; **подтверждение полностью удаляет урок на Latorn вместе с его шагами** — это разрушительно и не откатывается из локальных файлов.

### Удаление модуля

1. Удали запись модуля из массива `structure` в `structure.json`.
2. Перенумеруй оставшиеся модули, чтобы `section_position` оставалась непрерывным рядом с 1. Пересортируй массив по `section_position`.
3. **Удали локальную папку модуля** `courses/<course>/<module_pos_padded>/`. Через `Remove-Item -Recurse -Force`.
4. **Переименуй последующие папки модулей** под новые позиции.
5. Та же оговорка: удаление на Latorn происходит только через `sync_deletions=True` с подтверждением и сносит модуль со всем содержимым.

## Что аплоудер делает с твоими изменениями

После правки `structure.json` изменения можно отправить на Latorn:

```python
downloader.upload_structure()          # только структура
downloader.upload_course(sync_structure=True)  # структура + шаги
```

Поведение аплоудера:
- **Описание курса** (редактируемые поля `course_info`) → PUT /api/courses/{id} (только изменившиеся поля)
- **Название модуля** при существующем `section_id` → PUT /api/sections/{id}
- **Модуль** без `section_id` → POST /api/sections (создаёт новый)
- **Название урока** при существующем `lesson_id` → PUT /api/lessons/{id}
- **Урок в другом модуле** (расхождение с `lesson_info.sectionId`) → PUT /api/lessons/{id} с новым `sectionId`
- **Урок** без `lesson_id` → POST /api/lessons (создаёт новый)
- **Позиции** модулей и уроков приводятся в порядок перестановкой в две фазы после создания и переименований.
- Аплоудер **при значении по умолчанию `sync_deletions=False`** никогда не удаляет — только создаёт и обновляет. При `sync_deletions=True` он интерактивно спрашивает про удаление модулей и уроков, которые есть на Latorn, но отсутствуют локально. **На Latorn это удаляет саму сущность со всем содержимым.**

## Длина названий

Жёстких лимитов длины названий Latorn не документирует. Всё же держи названия короткими — длинные плохо переносятся в интерфейсе курса:
- Названия уроков: ориентир ≤ 64 символов.
- Названия модулей: ориентир ≤ 100 символов.
- Никогда не обрезай механически посреди слова — ищи естественную короткую форму.
- Если пользователь дал очень длинное название, предложи сокращённый вариант и дождись подтверждения перед сохранением.

## Ограничения

- Держи `section_position` и `position` уроков непрерывными целыми числами с 1 без пропусков — пропуски сбивают аплоудер.
- Не меняй `lesson_id` существующего урока — это разорвёт связь с содержимым на Latorn.
- Не меняй `section_id` существующего модуля — по той же причине.
- Максимум 16 шагов на урок (соблюдается в другом месте, но упомяни, если это уместно).

## Валидность JSON — обязательный шаг проверки

**После каждого Edit или Write в structure.json** сразу запускай:

```powershell
.\.venv\Scripts\python.exe -c "import json; json.load(open('courses/<course>/structure.json', encoding='utf-8')); print('OK')"
```

Если напечаталось что-то кроме `OK`, почини JSON, прежде чем продолжать. Частые причины:

- **Лишняя запятая** — самая частая ошибка. Возникает при удалении элемента массива или правке блока, который не был последним: `},` перед `]` или `},` перед `}` в конце объекта. После любого удаления или вставки в массив проверь, что у последнего элемента нет висящей запятой.
- **Пропущенная запятая** — возникает при вставке нового элемента, когда забыли добавить `,` после предыдущего.
- **Несовпадение скобок** — посчитай `{`/`}` и `[`/`]` в изменённом участке.

Не отчитывайся о готовности правки, пока команда проверки не напечатает `OK`.

## Порядок работы

1. Покажи пользователю сводку текущей структуры.
2. Спроси, что нужно поменять (или сразу действуй, если пользователь уже описал задачу).
3. Спланируй изменения и подтверди их с пользователем, если правка нетривиальна (перестановка нескольких модулей, массовые переименования).
4. Внеси изменения в `structure.json`.
5. Покажи сводку изменений в стиле диффа.
6. Напомни пользователю запустить `upload_structure()` (или `upload_course(sync_structure=True)`), чтобы отправить изменения на Latorn.
