# Разбор аргументов

Разбирай `$ARGUMENTS`, распознавая эти необязательные токены в любом порядке:

| Токен | Значение |
|---|---|
| Совпадает с именем курса (см. список ниже) | `course` |
| `build`, `update`, `search`, `search-history` | `action` |

**Известные курсы** — читай во время выполнения: перечисли все подпапки `courses/` (`Glob` с шаблоном `courses/*/` или PowerShell `Get-ChildItem courses -Directory`). Не зашивай имена курсов в код.

После разбора запроси недостающие обязательные значения через `AskUserQuestion`:

1. **course** — если не указан или не распознан, спроси одиночным выбором со списком папок внутри `courses/`.
2. **action** — если не указан, спроси с четырьмя вариантами:
   - **build** — собрать индекс с нуля (или пересобрать весь курс / модуль / урок)
   - **update** — обновить один шаг в существующем индексе
   - **search** — поиск по всему индексу курса
   - **search-history** — поиск только по пройденной части курса (до указанного урока)

---

# ACTION: build

Спроси (если не передано в аргументах):
- **scope** — что пересобрать:
  - **Весь курс** (по умолчанию)
  - **Модуль** → спроси номер модуля свободным текстом
  - **Урок** → спроси номер модуля + урока свободным текстом
  - **Шаг** → спроси номер модуля + урока + шага свободным текстом

Запусти:

```
.\.venv\Scripts\python.exe -m src.course_rag build --course <course> [--module-num <n>] [--lesson-num <n>] [--step-num <n>]
```

После завершения команды сообщи `files_count` и `chunks_count` из JSON-вывода.

---

# ACTION: update

Спроси путь к файлу шага, если он не передан. Ожидаемый формат:

```
courses/<course>/<module>/<lesson>/{pos:02d}_{type}/task.md   (task.html в HTML-курсах)
```

Запусти:

```
.\.venv\Scripts\python.exe -m src.course_rag update --course <course> --file <path>
```

После завершения команды подтверди, что шаг обновлён, и сообщи префикс его `chunk_id` из вывода.

---

# ACTION: search

Спроси поисковый запрос, если он не передан.

При желании сузь область — спроси, хочет ли пользователь отфильтровать по модулю / уроку / шагу (по умолчанию фильтра нет, поиск по всему курсу).

Запусти:

```
.\.venv\Scripts\python.exe -m src.course_rag search --course <course> --query "<query>" [--k 5] [--module <n>] [--lesson <n>] [--step <n>]
```

Показывай результаты нумерованным списком: `score`, `step_title`, `section_title`, расположение (`module-lesson-step`) и короткая выдержка из `page_content`.

---

# ACTION: search-history

Используй, когда пишешь урок и нужно проверить, что уже объясняли *до* текущего урока.

Спроси:
1. **query** — что искать
2. **module-to** + **lesson-to** — урок, который пишется (граница: ищется всё, что *до* этого урока)
3. **step-to** (необязательно) — дополнительно сузить до шагов раньше этой позиции

Правило границы по умолчанию: когда пишется урок `M/L`, ищи до конца `M/(L-1)`.

Запусти:

```
.\.venv\Scripts\python.exe -m src.course_rag search-history --course <course> --query "<query>" --module-to <n> --lesson-to <n> [--step-to <n>] [--k 5]
```

Показывай результаты так же, как в `search`.

# Общие правила

- Векторные индексы курсов лежат в `course_rag/<course>/`.
- Считай индекс каждого курса изолированным. Никогда не ищи по одному курсу, если задача про другой, — кроме случаев, когда пользователь прямо просит сравнение между курсами.
- При написании нового шага урока используй RAG курса как запасной источник контекста, если нужных прежних объяснений нет ни в контексте чата, ни в саммари уроков.
- Для проверок на преемственность вроде «объясняли ли мы X раньше?» бери `search-history` до границы предыдущего урока, а не поиск по всему курсу.
- Если задача добавляет или правит видимое студенту упоминание другого курса — задокументируй его через скилл /context-links.
- Не используй RAG курса по умолчанию для чисто локальных правок, когда нужный контекст уже есть в текущем уроке и его саммари.
- Поддерживаемые файлы индекса на курс:
  - `course_rag/<course>/index.faiss`
  - `course_rag/<course>/index.pkl`
  - `course_rag/<course>/metadata.json`
  - `course_rag/<course>/chunks.jsonl`
- Индекс покрывает только типы шагов, перечисленные в `EditorConfig.rag_indexed_step_types` (по умолчанию `["text"]`). Чтобы индексировать другие типы (например `review`), добавь их в этот список и пересобери индекс.
- После существенных правок проиндексированного шага запусти `update`, если индекс уже существует или пользователь просил держать его актуальным.
