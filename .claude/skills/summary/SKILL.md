# Разбор аргументов

Разбирай `$ARGUMENTS`, распознавая эти необязательные токены в любом порядке:

| Токен | Значение |
|---|---|
| Совпадает с именем курса (см. список ниже) | `course` |
| `script` или `llm` | `mode` |
| Первое оставшееся число | `module` |
| Второе оставшееся число | `lesson` |

**Известные курсы** — читай во время выполнения: перечисли все подпапки `courses/` (`Glob` с шаблоном `courses/*/` или PowerShell `Get-ChildItem courses -Directory`). Не зашивай имена курсов в код.

После разбора запроси недостающие обязательные значения через `AskUserQuestion`:

1. **course** — если не указан или не распознан, спроси одиночным выбором со списком папок внутри `courses/`.
2. **module** — если не указан, спроси числом свободным текстом (подпись: «Модуль»).
3. **lesson** — если не указан, предложи два варианта: «Урок (ввести номер)» или «Весь модуль». Если пользователь выбрал «Весь модуль», ставь scope = module.
4. **mode** — если не указан, спроси с двумя вариантами:
   - **script** — быстрая генерация через Python-скрипт (рекомендуется для batch-запуска)
   - **llm** — генерация агентом (читает HTML/JSON, пишет развёрнутое саммари с контекстом)

Область (scope) определяется тем, что передал пользователь:
- только курс → **весь курс** (все модули и уроки)
- курс + модуль → **модуль**
- курс + модуль + урок → **урок**

# MODE: script

Запусти готовый скрипт с флагами под нужную область:

| Область | Команда |
|---|---|
| Урок | `.\.venv\Scripts\python.exe -m src.utils.generate_lesson_summaries --course <course> --module <M> --lesson <L>` |
| Модуль | `.\.venv\Scripts\python.exe -m src.utils.generate_lesson_summaries --course <course> --module <M>` |
| Курс | `.\.venv\Scripts\python.exe -m src.utils.generate_lesson_summaries --course <course>` |

Скрипт:
- Строит TF-IDF индекс по всем файлам `task.md`/`task.html` курса (всегда по всему курсу — ради корректного IDF).
- Читает `lesson.json`, HTML-файлы шагов и `step.json` для тестовых шагов.
- Пишет `<module>-<lesson>_summary.md` рядом с каждым `lesson.json`.
- Перезаписывает существующие саммари.
- Принимает необязательные флаги `--module` и `--lesson`, чтобы ограничить, какие саммари писать.

**Когда использовать режим script:**
- Генерация саммари для одного урока, модуля или всего курса.
- Быстрая первичная индексация перед написанием новых уроков.
- В курсе уже есть настоящее содержимое (не заглушки).

**После завершения скрипта:** сообщи, сколько файлов создано/обновлено (разбери stdout скрипта).

**Заглушки в режиме script:** скрипт генерирует саммари и для уроков-заглушек — саммари получится пустоватым. Если целевые уроки заглушки, предупреди пользователя и предложи вместо этого сгенерировать план модуля (режим module, llm).

# MODE: llm — ОБЛАСТЬ «УРОК»

## Цель

Создать или обновить `courses/<course>/<module>/<lesson>/<module>-<lesson>_summary.md`, рассуждая LLM по реальному содержимому шагов.

## Проверка на заглушку

Перед чтением содержимого шагов открой `task.md` первого текстового шага (или `task.html` в HTML-курсах). Если там только текст-заглушка (например `Урок находится в стадии разработки.` или похожее) — урок является заглушкой.

**Если заглушка:** не генерируй саммари урока. Вместо этого спроси пользователя:
> Урок — заглушка. Сгенерировать план модуля вместо summary?

Если пользователь согласен, переключись в **РЕЖИМ МОДУЛЯ** (llm).

## Шаги

1. Найди `courses/<course>/<module>/<lesson>/`.
2. Прочитай `lesson.json`, чтобы получить список шагов. Для каждого шага:
   - `text` / `code` / `review`: читай `{pos:02d}_{type}/task.md` (или `task.html` в HTML-курсах).
   - `choice` / `matching` / `sorting` / `number` / `free-text` / `video`: читай `{pos:02d}_{type_safe}/step.json`, поле `"text"`.
3. Проверь, существует ли уже `<module>-<lesson>_summary.md`.
   - Существует → обнови под текущее состояние урока.
   - Нет → создай с нуля.

## Где хранить

`courses/<course>/<module>/<lesson>/<module>-<lesson>_summary.md`

## Что обязательно должно быть в саммари

- Короткая цель урока.
- Компактная структура урока: сколько теоретических шагов, шагов-вопросов, шагов на проверку человеком и задач на программирование (выведи из `lesson.json`).
- Основные идеи и введённые термины.
- Что студент должен понимать после этого урока.
- Если есть финальный практический HTML-шаг: что он делает и какой задел создаёт для следующего урока.
- Для курсов со сквозным проектом: текущая стадия проекта (сделано / не начато / что должен продвинуть следующий урок), конкретные уже задействованные артефакты (ключевые файлы, документы, папки) и короткая передача практики (какое действие студента продолжается дальше, какой формы ожидается промпт/задание, какой наблюдаемый результат должен быть целью следующего урока).
- Устоявшаяся терминология и договорённости по формулировкам.
- Что нельзя дословно повторять в следующем уроке.
- Какие примеры, артефакты и практические акценты уже использованы.

## Чего в саммари быть НЕ должно

- Больших скопированных фрагментов HTML.
- Полной пошаговой расшифровки урока.
- Случайных деталей, которые не помогают собрать следующий урок.

## Дополнительно про сквозную практику

Хорошее саммари позволяет следующему редактору ответить на три вопроса, не перечитывая весь HTML:
1. На какой стадии сейчас общий проект.
2. Какие конкретные артефакты уже доступны для переиспользования.
3. Каким должен быть следующий практический шаг в проекте.

## Финальная проверка (область «урок»)

1. Файл лежит в правильном месте.
2. Саммари отражает текущее состояние урока.
3. Теоретические шаги, практические шаги и артефакты вопросов/заданий описаны точно.
4. Саммари сжатое, полезное и пригодное для повторного использования в будущих задачах.

# MODE: llm — ОБЛАСТЬ «МОДУЛЬ»

## Цель

Создать или обновить `courses/<course>/<module>/<module>_module_plan.md`.

Этот файл — **навигационный якорь всего модуля**. Агенты читают его перед созданием новых уроков, чтобы понять, что уже пройдено, как уроки связаны и что модуль обещает.

## Шаг 1 — определить статус уроков

Просканируй `courses/<course>/<module>/` на предмет подпапок уроков. Для каждой папки прочитай `lesson.json` и открой `task.md`/`task.html` первого теоретического шага. Классифицируй каждый урок:

| Состояние | Значение |
|---|---|
| **заглушка** | Только текст-заглушка |
| **готовый** | Есть настоящее содержимое |

Классифицируй модуль как один из: **сплошные заглушки**, **смешанный**, **готовый**.

## Шаг 2 — загрузить структуру курса (если есть)

Поищи `courses/<course>/structure.json`. Запусти:

```
.\.venv\Scripts\python.exe -m src.utils.extract_course_structure --input courses/<course>/structure.json
```

Найди секцию, у которой `section_position` совпадает с номером модуля. Названия уроков из её массива `lessons` — источник истины.

## Шаг 3 — определить список уроков

**Если структура курса доступна:** используй эти названия уроков. О любом расхождении между структурой и реальными подпапками сообщи пользователю.

**Если структуры курса нет, а модуль состоит из заглушек или пуст:** предложи связный список из 4–6 уроков, который логично закрывает роль модуля в дуге курса. **Дождись подтверждения пользователя, прежде чем генерировать план.**

## Шаг 4 — собрать содержимое

- **Готовый модуль:** прочитай каждый `<module>-<lesson>_summary.md`. Если саммари урока нет, сначала прогони для него режим llm с областью «урок».
- **Смешанный модуль:** для готовых уроков используй саммари; уроки-заглушки описывай по подтверждённому списку уроков.
- **Модуль из одних заглушек:** план является планировочным документом. Собери структуру по подтверждённому списку уроков.

## Шаг 5 — написать или обновить `<module>_module_plan.md`

Путь к файлу: `courses/<course>/<module>/<module>_module_plan.md`.

### Обязательные разделы

```markdown
# План модуля <N> — актуальное состояние

## Модуль <N>: `<название модуля>`

<2–3 предложения: какую задачу решает модуль, как он вписывается в дугу курса,
 связь с предыдущим и следующим модулями.>

Сквозная рамка модуля: <1–2 предложения: концептуальный стержень, связывающий все уроки.>

## Краткая логика модуля

<Нумерованный список 4–6 пунктов: рассказ о том, как выстраивается понимание, — не просто названия уроков.>

## Статус уроков

<Однострочная сводка статусов.>

## Структура модуля

### Урок <module>-<lesson>. `<название урока>`

**Статус: <сгенерирован | не начат | частично готов>**

<Готовые уроки: перенеси или сожми из саммари урока.
 Заглушки и запланированные: опиши роль и запланированное содержимое, пометь как план.>

Актуальная структура урока:
- `01_text` — <что покрывает этот шаг>
- ...

---

## Сквозная практика в модуле   ← включать, только если у курса есть сквозная практическая рамка

<Как сквозной практический элемент (проект, фреймворк, рабочий процесс) используется в практических шагах модуля.>

## Что должен уметь студент после модуля

<Нумерованный список из 5–8 конкретных навыков. Используй «умеет», «понимает», «может объяснить».>

## Что важно удержать при дальнейшем редактировании

<Список: редакторские ограничения, чего избегать, от каких ошибок беречься,
 напоминание о лимите шагов (не больше 16 шагов на урок).>
```

### Тон

- **Готовый модуль:** уровень детализации как в `08_module_plan.md` — с реальным содержимым шагов.
- **Модуль-заглушка / план:** уровень детализации как в `09_module_plan.md` — запланированное содержимое явно помечено.

## Шаг 6 — финальная проверка (область «модуль»)

1. Файл лежит по правильному пути.
2. Название модуля и названия уроков совпадают с structure.json курса (если он есть).
3. Статусы уроков точно отражают реальное состояние файлов.
4. «Краткая логика» читается как связный рассказ.
5. В «Что важно удержать» есть напоминание о лимите в 16 шагов.
6. Если у курса есть сквозная практическая рамка: раздел «Сквозная практика» присутствует и согласован с практическими шагами.
7. Ни один урок не описан как готовый, если его HTML-файлы — заглушки.

# Как использовать планы модулей

- Перед созданием нового урока прочитай план модуля, чтобы понять, что уже пройдено и что осталось.
- Перед планированием нового модуля прочитай планы двух-трёх предыдущих модулей, чтобы не дублировать материал.
- Если плана модуля нет или он устарел, запусти `/summary <course> <module> llm` перед написанием.
- Если для готовых уроков нет саммари, запусти `/summary <course> <module> <lesson> llm` для каждого урока, прежде чем обновлять план модуля.
